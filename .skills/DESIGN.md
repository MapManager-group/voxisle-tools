# 洛林·方屿地图管理系统 Design System

## Overview

### 设计北极星

界面以“海图化的地图调度台”为视觉参照：深海军蓝导航像稳定的控制台外框，雾白与浅青工作区承载地图、申请、设置和站内信等高频任务，钴蓝与湖蓝负责标示当前操作与交互反馈。它是需要长期使用的产品工具，不是营销展示页。

### 产品语境

- **用户与任务：** 面向 Minecraft 地图服的玩家、地图管理员和审核人员，用于登录、申请地图、管理地图、处理记录与消息。
- **界面语言：** 当前以简体中文为主。组件文案使用直接、可执行的中文；世界名、服务器名和技术标识保留原始值。
- **使用场景：** 桌面管理优先，同时保证手机端可完成核心任务；列表与表单信息密度适中，关键操作需要快速识别。
- **界面属性：** 产品型界面。任务清晰度、状态反馈和跨页面一致性优先于装饰性表达。
- **视觉记忆点：** 深海军蓝侧栏与钴蓝—湖蓝交互高光是唯一主要表达，其余区域保持安静。
- **克制边界：** 表格、表单、弹窗和危险操作遵循熟悉的管理工具范式，不为个性改变操作位置或状态语义。
- **反向参照：** 不采用玻璃拟态、大面积渐变、霓虹赛博风、厚重投影或游戏 HUD 式装饰，以免降低数据可读性。

### 规范与运行时归属

本文件记录设计意图、语义角色和组件使用规范，不直接生成代码。当前运行时实现仍以下列文件为事实来源：

- `src/style/colors.js`：按钮、文字、描边、通知与渐变的语义颜色映射；
- `src/css/main.css` 及 `src/css/`：页面底色、表格、滚动条、选择控件和基础状态；
- `src/style/config.js`：内容最大宽度；
- `tailwind.config.js`：断点、动画和 Tailwind 扩展；
- `../src/components`：组件尺寸、圆角、阴影与交互状态。

新增页面应优先组合共享组件，不复制色值或在页面内建立局部设计系统。调整系统级色值、圆角或尺寸时，必须同步更新运行时所有者与本文件。

### 深色模式

深色模式使用 Slate 中性色保持与 Tailwind 运行时一致：页面工作台为 `#1E293B`（slate-800），卡片和侧栏主要为 `#0F172A`
（slate-900），交互或悬停表面为 `#334155`（slate-700）。文本转为 slate-100/300/400 层级，边界使用 slate-600/700/800。

深色模式不反转品牌语义：主操作仍为蓝青色系，成功、警告、危险保持原含义。不得仅以亮度变化表达选中、禁用或错误。

### 语义色

| 语义 | 默认色    | 深色辅助色     | 规则                             |
|------|-----------|----------------|----------------------------------|
| 成功 | `#72C800` | `#9ADB3B`      | 仅表示完成、通过或正向结果       |
| 警告 | `#CA8A04` | yellow-500/600 | 需要注意但可继续或可恢复         |
| 危险 | `#E4002B` | `#FF5C73`      | 删除、失败、不可逆或安全敏感操作 |
| 信息 | `#004C97` | `#3FC2D0`      | 中性信息、主要操作和当前状态     |

语义不能只靠颜色表达，必须同时使用明确文案，必要时配合 Material Design Icons 图标。危险色不得用于普通强调，成功绿不得作为装饰色。

### 交互与可读性

- 输入焦点使用 `#3FC2D0` 边框和浅青/深青四层焦点环，在浅色和深色背景上都必须可见。
- 选中文本使用浅青背景与 Navy 文字。
- 表格悬停使用 cyan-50/70；深色使用 slate-700/70。未读等选中态可使用更克制的 cyan 表面，但需保留文字状态。
- 正文不使用 Focus muted、成功绿或警告黄；这些颜色在白底上的小字号可读性不足。
- 高对比模式交还系统颜色，不隐藏边框、焦点或滚动条。

## Typography

产品使用无衬线系统栈。`Inter` 负责拉丁字符和数字，中文依次回退至 `PingFang SC`、`Microsoft YaHei` 和系统无衬线；不依赖远程字体才能正常工作。

| 层级       | 当前规格                | 使用场景                 |
|------------|-------------------------|--------------------------|
| 页面主标题 | 24px，`sm` 起 30px；700 | 页面唯一主标题           |
| 区块标题   | 20px；600               | 卡片内重要分区           |
| 正文/控件  | 14–16px；400–500        | 表单、列表、说明和按钮   |
| 字段标签   | 14px；600               | 输入字段和选择器标签     |
| 表头       | 12px；600；较宽字距     | 桌面表格列名             |
| 帮助文字   | 12px；400               | 字段说明、时间与次级信息 |

- 中文标题使用紧凑字距，正文行高约 1.5；长说明建议使用 1.5–1.75 行高。
- 中文界面不使用全大写建立层级。表头的 `uppercase` 只影响拉丁内容，不将中文替换为英文。
- 技术标识、世界名或需等宽对齐的数据可以使用 `mono`，普通正文不用等宽字体。
- 不使用斜体表达中文强调；用字重、层级或语义组件表达。
- 操作文案使用“登录”“保存设置”“确认删除”等具体动词，避免含糊的“提交”或独立“确定”。

## Layout

### 页面框架

- 顶部导航固定为 64px 高；桌面侧栏宽 256px，外侧保留 16px 间距并使用 16px 圆角。
- 主内容最大宽度为 72rem（Tailwind `max-w-6xl`）并居中。
- 页面内边距为移动端 16px、`sm` 起 24px、`lg` 起 32px。
- 页面标题与主体卡片通常相隔 24px；字段垂直间距为 20px；同组卡片与主要区块使用 24px 间距。
- 页面保持自然文档滚动。只有菜单、弹窗内容或明确的表格面板可拥有独立滚动区，不在共享壳层随意添加固定视口高度或
  `overflow: hidden`。

### 响应式规则

- 使用 Tailwind 标准断点并坚持移动优先：`sm` 扩展页面边距，`md` 组织双列表单，`lg` 切换桌面表格与侧栏，`xl` 展示固定侧栏与最大内容宽度。
- 表单默认单列；两个字段在 `md` 起双列，三个及以上字段可在 `xl` 起三列。
- 表格在 `lg` 以下隐藏表头，每个单元格通过 `data-label` 转为“标签—值”行；不以裁切后的桌面表格作为移动方案。
- 页面标题操作区允许换行或收缩，但主要操作不能被挤出视口。
- 不依赖悬停展示唯一信息。被截断的重要值需要点击、聚焦或详情页等移动端可用路径。

### 稳定性

- 加载区至少预留约 160px 高度，避免内容加载时页面跳动。
- 按钮进入禁用或忙碌状态时保持原尺寸，不用更长文案撑开布局。
- 图像与头像声明稳定尺寸；表格行、分页和表单帮助文字避免异步出现时推动主要操作。
- 全局滚动条为 8px、可见且可操作；深浅模式都保持轨道与滑块对比。

## Elevation & Depth

层级主要通过表面色、边界和间距建立，阴影只作轻微分离：

- 普通卡片：白色或半透明深色表面、低对比 1px 边框、短而柔和的蓝灰阴影。
- 可悬停卡片：仅上移约 2px并轻微增强阴影；不可点击卡片不使用悬浮动画制造错误暗示。
- 顶部导航：半透明白/深色表面配合背景模糊和底边线，表达固定层级。
- 侧栏：使用比工作台更深的表面和克制阴影，形成结构边界。
- 弹窗：允许更明显阴影；遮罩压暗背景，但不以玻璃效果替代清晰边界。

普通数据卡片、表格行和字段不使用厚重投影。一个区域最多由表面、边界、阴影三者中的两种承担层级，避免重复装饰。

## Shapes

- 按钮、输入框、选择器、侧栏条目和玩家头像使用 12px 圆角（`rounded-xl`）。
- 卡片、侧栏容器使用 16px 圆角（`rounded-2xl`）。
- 通知、紧凑提示和复选框悬停区使用 8px 圆角。
- 标签、状态胶囊和明确的圆形图标容器可使用全圆角；普通按钮不默认使用胶囊形。
- 玩家头像统一为圆角方形，不改为圆形或直角；不同页面通过尺寸而非轮廓区分用途。
- 边框通常为 1px。焦点环可以更宽，但不以粗静态边框制造层级。
- 危险操作沿用同一形状语言，只通过语义色、图标、位置与明确文案区分。

## Components

### 基础视觉状态

| 状态           | 视觉与行为                                       |
|----------------|--------------------------------------------------|
| 默认           | 清晰边界、可读标签和符合语义的表面               |
| 悬停           | 轻微表面或文字色变化；启用项显示指针光标         |
| 聚焦           | 可见焦点环和边框变化，不移除键盘焦点提示         |
| 按下/当前      | 比悬停更深的表面，同时提供字重、图标等非颜色线索 |
| 禁用           | 降低不透明度、使用禁止光标且不触发事件           |
| 忙碌           | 保持控件尺寸、阻止重复提交并显示可感知进度       |
| 成功/警告/错误 | 使用语义色、图标和明确中文文本，不仅改变颜色     |

加载默认使用共享旋转图标；只有能精确匹配最终内容几何时才使用骨架屏。动画必须支持 `prefers-reduced-motion`，关闭后仍能从静态状态理解进度。

### 按钮与操作

- 所有操作与导航分别使用原生 `button` 和链接语义，并通过 `BaseButton` 统一实现。
- 标准按钮最小高度 44px，紧凑按钮最小高度 32px；仅图标按钮最小点击框 40×40px。
- 同组操作使用 8px 间距；图标位于标签左侧，间距为 8px。
- `info` 是当前主要操作样式；`whiteDark` / `lightDark` 用于次级工具操作；outline 用于较低强调层级。
- `success` 仅用于明确的正向提交，`danger` 仅用于删除或不可逆动作。危险操作与安全主操作保持视觉或空间分离。
- 仅图标按钮必须提供 `title` 或可访问名称；不常见动作优先同时显示文字。
- 按钮组在窄屏允许换行，不通过缩小点击目标强行保持单行。

### 卡片与容器

- `CardBox` 是内容容器统一入口：默认 24px 内边距，表格卡片可取消内容内边距。
- 不在卡片内无意义嵌套相同阴影的卡片；嵌套表格容器主要依赖边界与间距。
- 卡片标题、主体和底部操作通过共享子组件组织，底部操作默认保留 24px 内边距。
- 可点击卡片启用 hover 变体并提供明确目标；静态统计卡片保持稳定。

### 导航与数据展示

- 侧栏为深 Navy，活动项通过高对比文字、字重和状态色共同标识。一级条目使用 12px 圆角和紧凑纵向间距。
- 顶部导航固定、半透明并有背景模糊；移动端菜单在其下方展开，保持 64px 定位基准。
- 使用 Material Design Icons（`@mdi/js`）作为统一图标来源。常规操作图标约 18–24px，不在同一控件混用图标体系。
- 表格桌面端使用 12px 半粗表头、20px 横向和 16px 纵向单元格内边距以及浅色斑马纹。
- 窄屏表格转为标签—值结构。每个 `td` 提供用户可理解的中文 `data-label`，不用接口字段名作为最终标签。
- 分页跟随表格，显示当前位置与总页数/总量；筛选变化后回到第一页。
- 标签与状态使用 `PillTag` 全圆角轮廓，但正文状态仍需可读标签。

### 表单

- 使用 `FormField`、`FormControl`、`FormSelect`、`FormCheckRadio` 和 `FormFilePicker` 组合字段，不在业务页复制输入框样式。
- 输入和选择器高度 44px，横向内边距 12px，文字 14px；文本域默认约 112px 高且禁止手动缩放。
- 字段标签位于控件上方，14px 半粗；帮助和错误文本位于控件下方，不用 placeholder 代替标签。
- 原生 `select` 是当前规范所有者；项目接受操作系统控制的展开菜单，但闭合状态必须与其他输入框同高、同圆角、同焦点样式。
- 明确的未选择态使用 `--请选择--` 或业务化 placeholder，不自动选择可能触发后续请求的有效值。
- 校验错误应保留已输入内容，说明问题与修改方式，并将焦点移至首个无效字段；不要只发通知后清空内容。
- 搜索框非空时应提供可聚焦的清除按钮；远程搜索遵循 300ms 防抖、输入法组合安全与过期请求保护。
- 文件上传同时说明格式、命名和大小限制；进度、失败、重试和取消状态保持在上传区域附近。

### 弹窗、通知与反馈

- 产品内确认使用 `CardBoxModal`，不得调用浏览器 `alert`、`confirm` 或 `prompt`。
- 弹窗标题明确对象，主要按钮使用真实动作，如“确认删除”；高风险弹窗默认聚焦取消或较安全操作。
- 弹窗应支持 Escape 关闭、焦点约束、关闭后恢复触发点焦点与长内容内部滚动。遮罩点击关闭只用于不会造成数据丢失的场景。
- Toast/全局通知由 `NotificationContainer` 与通知服务统一管理；通知确认结果，字段级错误仍在字段附近呈现。
- 页面内说明使用 `NotificationBar`。成功、警告、信息、危险保持统一色义，关闭按钮必须有可访问名称。
- 空状态说明当前为何为空和下一步动作；错误状态说明发生了什么以及如何重试。

### 头像与图像

- 所有 Minecraft 玩家头像通过共享 `UserAvatar` 展示，统一使用 12px 圆角方形。
- 列表紧凑头像常用 24×24px，个人资料或移动卡片可放大，但不拉伸或改变比例。
- 图片提供用户名或等价描述作为替代文本；远程头像加载失败时保留稳定占位尺寸。
- 不在单个页面用局部样式覆盖头像轮廓；视觉规则在共享组件维护。

### 动效

- 常规交互过渡为 150–250ms，使用自然 ease-in-out；用于颜色、轻微位移、显隐和菜单位置变化。
- 动效表达状态变化，不用于持续装饰。可悬停卡片最多上移 2px，按钮不夸张缩放。
- 加载旋转可以持续，但同时提供可感知加载区域或状态文案。
- 在 `prefers-reduced-motion: reduce` 下移除非必要位移、淡入淡出和连续旋转，保留即时状态切换。

### 内容与数据可视化

- 语气简洁、直接、友好但不过度卖萌。按钮用动作，标题用对象，错误用“问题 + 修复方式”。
- 同一动作跨页面保持同名，如“刷新”“标记已读”“确认删除”，不交替使用同义词。
- 时间、数量和状态显示单位或语境；空值统一使用“暂无”或短横线，避免混用 `null`、空字符串和英文占位。
- 图表优先用 Primary、Focus、Navy、Focus muted 构成顺序色板；成功和危险色只表达语义。图表同时提供文字、标签或表格替代。

## Do's and Don'ts

- **Do:** 使用深色导航、雾白工作台和克制蓝青高光建立稳定层级。
- **Do:** 通过共享组件维护按钮、字段、卡片、头像、通知和弹窗的一致状态。
- **Do:** 同时验证浅色、深色、键盘操作和移动端布局。
- **Do:** 让危险、成功和警告色保持语义专用，并始终配合文字。
- **Do:** 保持自然文档滚动、稳定加载占位和可见滚动条。
- **Don't:** 在业务页面复制色值、圆角、阴影或建立局部组件规范。
- **Don't:** 使用玻璃拟态、大面积渐变、霓虹光晕或厚重多层阴影装饰数据界面。
- **Don't:** 用圆形或直角替代统一的圆角方形玩家头像，或在单页覆盖共享头像样式。
- **Don't:** 只依靠悬停、颜色或图标传达关键操作和状态。
- **Don't:** 为适配桌面表格而裁切手机内容，或给共享页面壳层添加不必要的固定高度。
